Tabular Q-learning needs a row per state. DQN replaces the table with a network,
$Q_\theta(s,a)$, which makes it applicable to Atari frames and anything else with a large
state space — and immediately runs into lesson 6.04's deadly triad.

## The naive version, and why it fails

```python
# This diverges. Do not use it.
target = reward + gamma * Q(next_state).max()
loss = (Q(state)[action] - target) ** 2
```

Three problems, all of which follow from combining function approximation with bootstrapping:

**Correlated samples.** Consecutive transitions are highly correlated, violating the i.i.d.
assumption that SGD's convergence rests on (lesson 1.11). The network overfits to the
current stretch of trajectory and forgets what it learned earlier.

**A moving target.** The target depends on $Q_\theta$, which changes with every update.
The network is chasing a target that moves whenever it moves — and with function
approximation, updating $Q(s,a)$ also changes $Q(s',a')$ for similar states, which can
create a feedback loop that amplifies rather than settles.

**Maximisation bias.** The $\max$ over noisy estimates overestimates (lesson 6.05), and
function approximation makes the noise correlated across actions, which makes it worse.

## Experience replay

Store transitions in a buffer and train on random batches from it:

```python
import random
from collections import deque

import numpy as np
import torch

class ReplayBuffer:
    def __init__(self, capacity=1_000_000):
        self.buffer = deque(maxlen=capacity)

    def push(self, s, a, r, s_next, done):
        self.buffer.append((s, a, r, s_next, done))

    def sample(self, batch_size, device):
        batch = random.sample(self.buffer, batch_size)
        s, a, r, s2, d = zip(*batch)
        to = lambda x, dt: torch.as_tensor(np.array(x), dtype=dt, device=device)
        return (to(s, torch.float32), to(a, torch.int64), to(r, torch.float32),
                to(s2, torch.float32), to(d, torch.float32))
```

This does two things. It **breaks correlation** by sampling uniformly from a large history.
And it **reuses each transition many times**, which matters enormously when environment
interaction is the expensive part.

Replay is only possible because Q-learning is off-policy (lesson 6.05). Old transitions were
generated by an old policy, and Q-learning does not care.

## Target networks

Keep a frozen copy of the network for computing targets:

$$
y = r + \gamma \max_{a'} Q_{\theta^-}(s', a')
$$

```python
target_net = copy.deepcopy(q_net)
for p in target_net.parameters():
    p.requires_grad_(False)

# Every C steps (typically 1,000-10,000):
target_net.load_state_dict(q_net.state_dict())

# Or a soft update every step, which is smoother:
with torch.no_grad():
    for tp, p in zip(target_net.parameters(), q_net.parameters()):
        tp.mul_(1 - tau).add_(tau * p)          # tau ~ 0.005
```

::: key
The target network makes the regression target **stationary between updates**. Instead of
chasing a moving target, the network solves a fixed supervised problem for $C$ steps, then
the target moves once.

This is the single most important stabilisation in deep RL. Remove it and DQN diverges on
almost every task. It converts an unstable fixed-point iteration into a sequence of stable
supervised problems — exactly the structure that lesson 6.03's generalised policy iteration
describes.
:::

## The full loop

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def dqn_train(env, q_net, target_net, buffer, opt, steps=1_000_000,
              batch_size=32, gamma=0.99, target_update=1000,
              eps_start=1.0, eps_end=0.05, eps_decay=100_000, device='cuda'):
    state = env.reset()
    for step in range(steps):
        eps = max(eps_end, eps_start - step * (eps_start - eps_end) / eps_decay)
        if random.random() < eps:
            action = env.action_space.sample()
        else:
            with torch.no_grad():
                action = q_net(torch.as_tensor(state, device=device)[None]).argmax().item()

        next_state, reward, done = env.step(action)
        buffer.push(state, action, reward, next_state, float(done))
        state = env.reset() if done else next_state

        if len(buffer.buffer) < 10_000:         # warm up before learning
            continue

        s, a, r, s2, d = buffer.sample(batch_size, device)
        q = q_net(s).gather(1, a[:, None]).squeeze(1)        # lesson 2.04

        with torch.no_grad():
            # Double DQN: select with the online net, evaluate with the target.
            best = q_net(s2).argmax(1, keepdim=True)
            q_next = target_net(s2).gather(1, best).squeeze(1)
            target = r + gamma * q_next * (1 - d)

        loss = F.smooth_l1_loss(q, target)      # Huber: robust to outlier TD errors
        opt.zero_grad(set_to_none=True)
        loss.backward()
        nn.utils.clip_grad_norm_(q_net.parameters(), 10.0)
        opt.step()

        if step % target_update == 0:
            target_net.load_state_dict(q_net.state_dict())
```

Three details worth noting. The **Huber loss** bounds the influence of large TD errors,
which are common early in training. The **warm-up** fills the buffer before learning, so
early batches are not drawn from twenty highly correlated transitions. And **Double DQN** is
folded in at no cost — selecting with the online network and evaluating with the target
gives most of Double Q-learning's benefit with no extra network.

## The improvements

Rainbow combined six extensions, each worth a measurable amount:

| Extension | What it does |
|---|---|
| Double DQN | Decouples selection from evaluation (lesson 6.05) |
| Prioritised replay | Samples high-TD-error transitions more often |
| Dueling networks | Separates $V(s)$ and $A(s,a)$ heads |
| Multi-step returns | $n$-step targets instead of one step (lesson 6.04) |
| Distributional (C51) | Models the full return distribution, not its mean |
| Noisy nets | Learned parameter noise replaces $\epsilon$-greedy |

**Dueling** is the most instructive. Split the head into a state-value stream and an
advantage stream:

$$
Q(s,a) = V(s) + \left(A(s,a) - \frac{1}{|\mathcal{A}|}\sum_{a'}A(s,a')\right)
$$

The subtraction removes the identifiability problem — without it, adding a constant to $V$
and subtracting it from $A$ leaves $Q$ unchanged, so the split is not determined. It helps
most where the action does not matter much, since $V$ can be learned from every transition
regardless of which action was taken.

## Where DQN stops

::: warning
DQN requires $\arg\max_a Q(s,a)$, which means **enumerating the actions**. That confines it
to discrete, small action spaces.

It does not apply to continuous control (a robot joint angle) or to a language model's
128,000-token action space. Both need policy gradient methods, which is lesson 6.07.

DQN is also notoriously sensitive to hyperparameters and seeds. Published Atari results
routinely hide large variance across seeds — report the spread, per lesson 2.15.
:::

::: exercise
Your DQN's Q-values grow steadily during training and reach 1,000, while the true maximum
achievable return is about 20. What is happening?
:::

::: solution
**Value divergence from the deadly triad**, with maximisation bias driving it.

**The mechanism.** The $\max$ over noisy Q-estimates is biased upward (lesson 6.05). With
function approximation, updating $Q(s,a)$ generalises to nearby states, so an
overestimate at one state raises the target at others, which raises their estimates, which
raises the first one's target again. There is no ceiling in the loss — the network is
regressing to its own inflated output — so the values grow without bound.

**Diagnose in this order:**

1. **Is the target network being used and updated?** Print `id(q_net) is id(target_net)` and
   confirm `load_state_dict` is actually being called. A target net that is never updated, or
   is accidentally the same object, is the most common cause.

2. **Is `torch.no_grad()` around the target computation?** Without it, gradients flow into
   the target and the network optimises both sides of the regression toward each other —
   which diverges immediately.

3. **Is the terminal mask correct?** `target = r + gamma * q_next * (1 - done)`. If `done`
   is not applied, terminal states bootstrap from a next state that does not exist, and
   values accumulate indefinitely around episode boundaries.

4. **Is the reward scale sane?** Values should be roughly bounded by
   $r_{\max}/(1-\gamma)$. At $\gamma = 0.99$ and $r_{\max} = 1$ that is 100. Values of 1,000
   with a max return of 20 are impossible for any correct implementation, which points
   strongly at 2 or 3.

**Fixes, once the bugs are excluded:**

- **Double DQN**, if not already in use. It directly attacks the maximisation bias and is
  usually sufficient.
- **Slower target updates** — raise `target_update`, or lower $\tau$ for soft updates. This
  gives the online network longer to settle against a fixed target.
- **Huber loss instead of MSE**, bounding the gradient from large TD errors.
- **Clip rewards** to $[-1, 1]$, as the original DQN paper did. Crude, and it changes the
  problem, but it bounds the value scale.
- **Lower the learning rate.** Divergence is often just too large a step in an unstable
  iteration.

**In practice:** items 1–3 account for most real cases. A value of 1,000 against a true 20
is too extreme for bias alone — look for the bug before tuning.
:::

## What to carry forward

- Replay breaks sample correlation and reuses expensive experience; it needs off-policy learning.
- The target network makes the regression stationary between updates — it is the key stabiliser.
- Double DQN comes free: select with the online net, evaluate with the target.
- Huber loss, gradient clipping and a warm-up are standard, not optional.
- DQN needs an $\arg\max$ over actions, so it cannot do continuous or very large action spaces.
