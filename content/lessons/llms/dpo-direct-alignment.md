DPO's contribution is an observation: the RLHF objective has a closed-form optimal policy,
and that closed form can be inverted to express the reward in terms of the policy. Substitute
it into the reward model's loss and the reward model disappears entirely.

## The derivation

The KL-constrained objective from lesson 5.08 has a known optimum:

$$
\pi^*(y\mid x) = \frac{1}{Z(x)}\,\pi_{\text{ref}}(y\mid x)\exp\!\left(\frac{1}{\beta}r(x,y)\right)
$$

This is standard — maximising $\mathbb{E}[r] - \beta D_{\text{KL}}$ over distributions gives
a Boltzmann distribution tilted by the reward.

Solve for $r$:

$$
r(x,y) = \beta\log\frac{\pi^*(y\mid x)}{\pi_{\text{ref}}(y\mid x)} + \beta\log Z(x)
$$

Now substitute into the Bradley–Terry loss of lesson 5.07. The partition function $Z(x)$
depends only on the prompt, so it appears in both terms of the difference and **cancels**:

$$
\mathcal{L}_{\text{DPO}} = -\mathbb{E}\left[\log\sigma\!\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\right)\right]
$$

::: key
The intractable $Z(x)$ cancelling is what makes DPO work. Everything remaining is
computable with two forward passes per response — one through the policy, one through the
frozen reference.

**The language model is its own reward model**, defined implicitly by its log-ratio against
the reference.
:::

## The implementation

```python
import torch
import torch.nn.functional as F

def dpo_loss(policy, ref, batch, beta=0.1):
    """batch has chosen and rejected completions for the same prompts."""
    pol_chosen   = sequence_logprob(policy, batch['chosen'])
    pol_rejected = sequence_logprob(policy, batch['rejected'])
    with torch.no_grad():
        ref_chosen   = sequence_logprob(ref, batch['chosen'])
        ref_rejected = sequence_logprob(ref, batch['rejected'])

    logits = beta * ((pol_chosen - ref_chosen) - (pol_rejected - ref_rejected))
    loss = -F.logsigmoid(logits).mean()

    metrics = {
        'accuracy':      (logits > 0).float().mean(),
        'margin':        logits.mean(),
        'chosen_reward': beta * (pol_chosen - ref_chosen).mean(),
        'reject_reward': beta * (pol_rejected - ref_rejected).mean(),
    }
    return loss, metrics


def sequence_logprob(model, batch):
    """Sum of token log-probabilities over the response only."""
    logits = model(batch['input_ids'][:, :-1]).log_softmax(-1)
    labels = batch['input_ids'][:, 1:]
    per_token = logits.gather(2, labels.unsqueeze(-1)).squeeze(-1)   # lesson 2.04
    return (per_token * batch['response_mask'][:, 1:]).sum(-1)
```

The `response_mask` matters for the same reason as SFT's prompt masking (lesson 5.05):
including prompt tokens adds a large, identical term to both sides that dilutes the signal.

## What it simplifies

| | RLHF (PPO) | DPO |
|---|---|---|
| Models in memory | 4 | 2 |
| Generation during training | Yes | No |
| Value function | Yes | No |
| Stability | Fragile | Comparable to SFT |
| Main hyperparameters | ~10 | $\beta$, learning rate |

No rollouts is the biggest practical difference. PPO's loop generates, scores, and trains —
generation is slow and hard to parallelise efficiently. DPO is an ordinary supervised loop
over a fixed dataset.

::: check
DPO's derivation depends on one cancellation. What cancels, and why?

- [x] The partition function $Z(x)$, because it depends only on the prompt and so appears identically in both terms of the Bradley–Terry difference
  > That intractable term disappearing is what makes DPO computable: two forward passes per response, one through the policy and one through the frozen reference. The language model becomes its own reward model, defined by its log-ratio.
- [ ] The reference policy, which is the same in both terms
  > The reference appears in both terms but with *different* responses, so it does not cancel — it is exactly what the log-ratio is measured against.
- [ ] The KL penalty, which is absorbed into $\beta$
  > $\beta$ carries the KL strength through into the DPO loss rather than removing it.
- [ ] The value function, which is not needed for preference data
  > There is no value function in this derivation to cancel; DPO not needing one is a consequence, not the mechanism.
:::

## What it gives up

::: warning
**DPO is off-policy.** It trains on a fixed preference dataset generated by *some other*
policy. PPO trains on samples from the current policy, so it receives feedback on what it
actually produces now.

The consequence: as the policy moves away from the data-generating distribution, the
preference pairs become less informative about its current behaviour. There is no mechanism
for collecting feedback on the failure modes the policy develops during training.

This is why iterative DPO exists — generate with the current policy, collect preferences on
*those* samples, retrain, repeat. It recovers much of the on-policy benefit at the cost of
the simplicity that made DPO attractive.
:::

Two further limitations:

**No reward model to reuse.** A reward model is independently useful — for best-of-$n$
sampling, for filtering synthetic data, for evaluation. DPO produces none.

**Both log-probabilities can fall.** The loss only constrains the *difference*. A common
observation is that $\log\pi_\theta(y_w)$ decreases during DPO training while
$\log\pi_\theta(y_l)$ decreases faster. The objective is satisfied and the model has become
less likely to produce the preferred response. Log both — this is not visible in the loss.

::: check
DPO removes the reward model and the value model. What does it give up relative to PPO?

- [x] Online exploration — it learns from a fixed preference dataset rather than from responses the current policy generates
  > PPO samples fresh completions and scores them, so it can discover behaviours absent from the dataset. DPO is limited to the preferences it was given, which is why iterative and online DPO variants exist.
- [ ] The KL constraint, which is absent from DPO
  > The constraint is built into the objective through $\beta$ and the reference model.
- [ ] The ability to use preference data at all
  > Preference data is exactly what it consumes.
- [ ] Stability — DPO is the less stable of the two in practice
  > It is generally the more stable, which is much of its appeal.
:::

## The family

**IPO** replaces the logistic loss with a squared one, bounding how far the model pushes
any single pair:

$$
\mathcal{L}_{\text{IPO}} = \left(\log\frac{\pi_\theta(y_w)\pi_{\text{ref}}(y_l)}{\pi_\theta(y_l)\pi_{\text{ref}}(y_w)} - \frac{1}{2\beta}\right)^2
$$

DPO's logistic loss keeps pushing on pairs it already ranks correctly, which drives
overfitting on deterministic preferences. IPO's target stops that.

**KTO** drops pairs entirely, needing only a binary good/bad label per response. Far easier
to collect — thumbs up and down from production traffic — at some cost in signal.

**ORPO** merges SFT and preference optimisation into one stage with an odds-ratio penalty,
removing the need for a separate reference model.

**SimPO** removes the reference model by using length-normalised average log-probability,
which also addresses DPO's length bias directly.

## Choosing $\beta$

$\beta$ controls how far the policy may move from the reference — the same role as in
RLHF's KL term.

| $\beta$ | Behaviour |
|---|---|
| 0.01 | Large movement; risk of degeneration |
| 0.1 | The standard default |
| 0.5 | Conservative; may barely change the model |

Diagnose by logging `chosen_reward` and `reject_reward` — the implicit rewards. Healthy
training shows the chosen reward roughly flat or slightly rising and the rejected reward
falling. Both falling sharply means $\beta$ is too low.

::: exercise
DPO training reaches 95% preference accuracy but the model produces shorter, less helpful
answers than the SFT model it started from. What happened?
:::

::: solution
**The model is satisfying the objective by suppressing the rejected responses rather than
promoting the chosen ones.** The loss only constrains the difference, and pushing
$\log\pi(y_l)$ down is easier than pushing $\log\pi(y_w)$ up.

**Confirm it by logging both implicit rewards.** The signature is:

```
chosen_reward:  -0.4  (negative and falling)
reject_reward:  -3.1  (falling much faster)
margin:          2.7  (large, so accuracy is high)
```

Both negative and falling means the policy assigns *lower* probability to both responses
than the reference does — it has moved away from good and bad alike, just further from bad.
The 95% accuracy is measuring the gap, which says nothing about absolute quality.

**Why shorter.** Longer responses have more tokens, so their summed log-probability is more
negative and easier to reduce. Suppressing probability mass has a length-dependent effect,
so the model systematically shifts toward shorter output — the mirror image of RLHF's length
bias (lesson 5.07), running in the opposite direction.

**Fixes, in order:**

1. **Raise $\beta$** to 0.3–0.5. This constrains movement from the reference directly and
   is the immediate lever.
2. **Add an SFT term** on the chosen responses:
   ```python
   loss = dpo_loss + alpha * (-pol_chosen.mean() / n_tokens)
   ```
   with $\alpha \approx 0.1$. This anchors $\log\pi(y_w)$ so it cannot fall, which addresses
   the mechanism directly. Several variants (RPO, DPOP) formalise this.
3. **Use length-normalised log-probabilities** (SimPO's approach) so the objective does not
   reward brevity mechanically.
4. **Switch to IPO**, whose bounded target stops the model pushing indefinitely on pairs it
   already ranks correctly.

**What not to do:** train longer. Accuracy rising to 99% means the degeneration is
proceeding, not that the model is improving. Preference accuracy is a diagnostic, not an
objective — the same confusion as reading a reward model's own score in lesson 5.07.
:::

## What to carry forward

- The RLHF optimum has a closed form; inverting it makes the model its own reward model.
- $Z(x)$ cancels in the Bradley–Terry difference — that cancellation is the whole trick.
- Two models, no rollouts, no value function, roughly SFT-level stability.
- Off-policy: the data reflects a different policy than the one being trained.
- Log both implicit rewards; the loss cannot tell you if both are falling.
